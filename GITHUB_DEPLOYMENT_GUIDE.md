# GitHub Actions & Automated Deployment Guide

## Overview

এই গাইডে GitHub Actions ব্যবহার করে automated APK build এবং Heroku deployment সেটআপ আছে।

## GitHub Actions Workflow

### Build & Release Workflow (`.github/workflows/build-and-release.yml`)

**Features:**
- ✅ Automatic Android APK build
- ✅ GitHub Releases management
- ✅ Heroku deployment (Server + Client)
- ✅ APK artifacts upload
- ✅ Build on push to main branch

**What it does:**
1. Checks out code
2. Sets up Android SDK
3. Builds Debug APK
4. Builds Release APK
5. Uploads artifacts
6. Creates GitHub Release
7. Deploys to Heroku

## Setup Instructions

### 1. Create GitHub Repository

```bash
cd c:\New folder\school_n
git remote set-url origin https://github.com/YOUR_USERNAME/school_n.git
git push -u origin main
```

### 2. Generate GitHub Token

1. Go to **https://github.com/settings/tokens**
2. Click "Generate new token" → "Generate new token (classic)"
3. Select scopes:
   - `repo` (full control of private repositories)
   - `workflow` (update GitHub Actions workflows)
4. Copy token
5. Add to GitHub: **Repository → Settings → Secrets and variables → Actions → New repository secret**
   - Name: `GITHUB_TOKEN`
   - Value: `(paste token)`

### 3. Generate Heroku API Token

1. Go to **https://dashboard.heroku.com/account**
2. Scroll to "API Key" section
3. Click "Reveal" and copy token
4. Add to GitHub Secrets:
   - Name: `HEROKU_API_KEY`
   - Value: `(paste token)`

### 4. Android Release Keystore (Optional)

For production APK signing:

```bash
# Generate keystore
keytool -genkey -v -keystore android/app/release-key.keystore \
  -keyalg RSA -keysize 2048 -validity 10000 -alias school-app

# Add to GitHub Secrets:
# KEYSTORE_PASSWORD, KEY_ALIAS, KEY_PASSWORD
```

## Workflow Triggers

### Automatic Build on Push

```yaml
on:
  push:
    branches:
      - main
      - develop
```

**এই হবে যখন:**
- `main` ব্র্যাঞ্চে push করবেন
- `develop` ব্র্যাঞ্চে push করবেন

### Manual Trigger (Workflow Dispatch)

GitHub Actions → Build and Release → Run workflow

## Deployment Process

### Step 1: Code Changes
```bash
# Make changes locally
git add .
git commit -m "feat: add new feature"
git push origin main
```

### Step 2: GitHub Actions Runs
- Automatically triggered on push
- Builds APK
- Creates Release
- Uploads artifacts

### Step 3: View Build Status
- Go to **Repository → Actions**
- See build progress in real-time

### Step 4: Download APK
- Go to **Repository → Releases**
- Download APK from latest release

### Step 5: Heroku Deployment
- Server auto-deploys to https://school-server.herokuapp.com
- Client auto-deploys to https://school-client.herokuapp.com

---

## Workflow Jobs

### 1. **build** Job
Runs on: `ubuntu-latest`

**Steps:**
1. Checkout code
2. Setup JDK 11
3. Setup Android SDK (API 34)
4. Build Debug APK
5. Build Release APK
6. Upload Debug APK artifact
7. Upload Release APK artifact
8. Create GitHub Release
9. Upload Release APK to GitHub Release

### 2. **deploy** Job
Runs after: `build` job succeeds
Runs on: `ubuntu-latest`

**Steps:**
1. Setup Node.js 18
2. Install Server dependencies
3. Build Server TypeScript
4. Deploy Server to Heroku
5. Install Client dependencies
6. Build Client
7. Deploy Client to Heroku

## Environment Variables

### For GitHub Actions

Add these to **Repository → Settings → Secrets and variables → Actions:**

```
GITHUB_TOKEN        → (auto-generated by GitHub)
HEROKU_API_KEY      → (from Heroku dashboard)
KEYSTORE_PASSWORD   → (optional, for release APK)
KEY_ALIAS           → (optional, for release APK)
KEY_PASSWORD        → (optional, for release APK)
```

### For Heroku Apps

**Server (school-server):**
```
MONGO_URI           → MongoDB connection string
JWT_SECRET          → JWT signing key
FRONTEND_URL        → https://school-client.herokuapp.com
SMS_ENABLED         → true/false
SMS_API_KEY         → Anoncify API key
```

**Client (school-client):**
```
NEXT_PUBLIC_API_URL → https://school-server.herokuapp.com/api
```

## Monitoring & Debugging

### View Workflow Logs

1. **Repository → Actions**
2. **Click on workflow run**
3. **View step logs**

### Common Issues

| Issue | Solution |
|-------|----------|
| Build fails | Check Android SDK setup, Java version |
| Deploy fails | Verify Heroku API token, app names |
| APK too large | Enable ProGuard minification |
| Build timeout | Increase timeout in workflow (default 60 min) |

## Manual Build (Without GitHub Actions)

If GitHub Actions not available:

### Build Server
```bash
cd server
npm install
npm run build
git push heroku main
```

### Build Client
```bash
cd client
npm install
npm run build
git push heroku main
```

### Build Android APK
```bash
cd android
./gradlew assembleDebug      # Debug APK
./gradlew assembleRelease    # Release APK
# APK output: app/build/outputs/apk/
```

## Release Management

### Creating Manual Releases

```bash
# Tag current commit
git tag v1.0.0
git push origin v1.0.0

# GitHub automatically creates release from tag
```

### Version Numbering

Use semantic versioning:
- `v1.0.0` - Major release
- `v1.0.1` - Patch fix
- `v1.1.0` - Minor feature
- `v2.0.0` - Major breaking changes
