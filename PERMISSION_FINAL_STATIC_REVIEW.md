# Permission Final Static Review

Static review completed. Tests were not run.

## Review basis

Reviewed the current frontend central permission matrix and backend route mounting/guard files after the permission patches.

Important backend mount order observed:

- `/api/academic/classes` uses the safe class route before legacy `/api/academic`.
- `/api/academic/subjects` uses the safe subject route before legacy `/api/academic`.
- `/api/academic/exams` uses the scoped exam route before legacy `/api/academic`.
- `/api/academic/results/me` is mounted before `/api/academic/results`.
- `/api/academic/results` uses the safe result route before legacy `/api/academic`.
- `/api/attendance` mounts the scoped `/me` route before the old attendance router.

Reusable scope resolver now exists at:

- `src/services/actorScope.service.ts`

It is delegated through:

- `src/services/permissionPolicy.ts`

## Cross-cutting findings

### Stronger areas after patches

- Academic classes, subjects, exams, and results now use safe route mounts before legacy academic routes.
- Result management has explicit entry, approval, publish, and delete guards.
- Exam management has scoped read and management/publish guards through `examsScoped.ts`.
- ID card management and read/download now have route-level guards.
- Site settings require auth, head/admin/super_admin, institution-scoped queries, secret masking, and audit logs.
- Leave + own attendance now support employee leave and scoped `/attendance/me`.
- Actor scope resolver exists and permissionPolicy delegates to it.

### Highest remaining risks

1. `/api/students` needs final scoped review for class_teacher assigned class and normal teacher blocking.
2. `/api/library` needs own-issued/read-only vs manage-role verification.
3. `/api/sms-monitoring` needs backend role + institution/global scope verification.
4. Syllabus, class routine, homework, and attendance mark routes should be converted to the reusable `actorScope.service.ts` if not already done.
5. Frontend `librarian` is not a first-class role in `types/index.ts`; `normalizeUserRole()` maps librarian to staff. This can hide librarian-specific UI and should be fixed in frontend type enum and permission matrix.
6. Frontend exam page component-level action hiding was previously blocked; central route/sidebar policy is correct, but page buttons should be manually rechecked.
7. `/api/leave-application` is not the mounted backend route; mounted route is `/api/leaves`. Add an alias if required by clients.

## Conclusion

Static review completed. Tests were not run. The most sensitive academic result, exam, subject, class, ID card, site settings, leave, and own-attendance paths have backend guards or scoped routes in place, but student list, library, SMS monitoring, syllabus/routine/homework, and attendance mark still need deeper static hardening before the permission model can be considered complete.
